Почему 201, а не 200?<br>
201 - статус успешного создания нового объекта. 200 - просто для успешных операций, которые ничего не создают.<br>

Это заголовок, который означает, что переданные данные будут в формате JSON.<br>
## 4. PUT — редактировать
### 04-update.png
![04-update.png](Screenshots/04-update.png)\
Чем PUT отличается от POST?<br>
PUT - обновляет существующий объект, POST - создаёт новый.<br>
Почему URL другой (/comments/{id}, а не /posts/{id}/comments)?<br>
URL для PUT указывает на уже существующий комментарий (объект) в таблице комментариев, когда как для POST он указывает на комментарии к отдельному посту.<br>
## 5. DELETE — удалить
### 05-delete.png
![05-delete.png](Screenshots/05-delete.png)\
Перечислите 4 HTTP-глагола.<br> 
GET, POST, PUT, DELETE.<br>
Какой код ответа у каждого и почему?<br>
GET - 200, успешно найден.<br>
POST - 201, успешно создан.<br>
PUT - 200, успешно обновлён.<br>
DELETE - 204, успешно удалён, нет контента.<br>

## 10. Сравнение кода
Сравните vanilla JS и React по пунктам:<br>
— Где хранится состояние (список комментариев, текст формы)?<br>
В vanilla JS состояние хранится в DOM и глобальных переменных: список комментариев в переменной data, текст формы читается напрямую из поля ввода. В React всё состояние централизовано в хуках useState это список в items, текст формы в text, ID редактируемого комментария в editId<br>
— Как обновляется список после добавления?<br>
В vanilla JS после отправки комментария нужно вручную вызвать loadItems(), которая формирует HTML-строку и вставляет её через innerHTML, полностью перерисовывая список, а в React достаточно вызвать setItems(data.items): React сам сравнивает виртуальный DOM и обновляет только изменившиеся элементы.<br>
— Как реализовано редактирование?<br>
В vanilla JS редактирование требует ручного перестраивания DOM , а в React редактирование реализовано через условный рендер: одна условная конструкция позволяет автоматически переключатся между просмотром и редактированием.<br>
— Как защищаемся от XSS?<br>
В vanilla JS нужно вручную вызывать функцию esc() для каждого выводимого поля,если забыть - дыра в безопасности. React автоматически всё экранирует.<br>

## 13. XSS
### 15-xss.png
![15-xss.png](Screenshots/15-xss.png)\
Как vanilla JS и React защищаются от XSS?<br>
В vanilla JS нужно вручную вызывать функцию esc() для каждого выводимого поля,если забыть - дыра в безопасности. React автоматически всё экранирует.<br>
Какой способ надёжнее?<br>
Безусловно способ React'а надёжнее, так как каждый текст экранируется, банально невозможно забыть защититься от XSS.<br>
